Git uses the established Windows GitHub CLI credential helper:
  /mnt/c/Program Files/GitHub CLI/gh.exe
No credentials are displayed, stored by this script or relayed over SSH. Push is
an ordinary fast-forward push; there is no force, rebase, merge or branch retry.
The script fetches the public branch afterward, creates a detached verification
worktree, and verifies its actual published bundle/runtime/v2/README bytes.

It then updates only existing PR #1's body using gh api PATCH --input - with JSON

response body, final GET body, commit and unchanged draft state are verified.
It does not create a PR, post a comment, mark ready, merge or change the title.

Terminal local states:
* bundle_ready: verified local bytes, no remote publication claimed.
* published: fetched repository bytes and PR body both verified.
* published_repo_pr_update_failed: repository publication verified, PR body failed;
  the verified commit remains recorded and no automatic retry is allowed.
* failed/interrupted: diagnostics retained; if interruption occurred during push,
  remote_push_may_have_completed is recorded. Never assume nothing was published.

Every transition has an atomic status.json and separate historical JSON receipt.
The control-directory lock refuses duplicate local workers. A prior uncertain,
failed or partially published receipt requires explicit reconciliation, not an
automatic retry. Fresh source/bundle mismatches are not repaired by this helper.
Successful published receipts can be reverified idempotently against identical
bytes. No bulky raw-data revalidation is claimed by postprocessing.
